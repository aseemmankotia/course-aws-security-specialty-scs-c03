## Chapter 6: IAM Troubleshooting: Denies, Access Analyzer, and Least Privilege — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | IAM policy evaluation order: what happens when an SCP has Deny and an identity policy has Allow for the same action? | SCP Deny ALWAYS wins. Evaluation order: 1) Explicit Deny (SCP, permissions boundary, identity policy) → denied, 2) SCP Allow → continue, 3) Permissions boundary Allow → continue, 4) Identity-based or resource-based Allow → allowed. Exam tip: SCPs create guardrails that cannot be bypassed by any identity policy. |
| 2 | IAM Access Analyzer: what is the maximum CloudTrail analysis period for policy generation? | 90 days. Access Analyzer analyzes CloudTrail events from the past 90 days to generate least-privilege policies. Exam tip: Longer analysis period = more accurate policies but 90 days is the hard limit. |
| 3 | CloudTrail errorCode: AccessDenied vs. InvalidPermission.NotFound - what's the difference? | AccessDenied = explicit deny in policy (SCP, identity policy, permissions boundary). InvalidPermission.NotFound = missing required permission like iam:PassRole or dependent action. Exam tip: InvalidPermission.NotFound often indicates PassRole issues when creating resources that need IAM roles. |
| 4 | What does IAM Policy Simulator NOT evaluate? | Does NOT evaluate: 1) Resource-based policies on target resources (like S3 bucket policies), 2) SCPs by default (can optionally include), 3) VPC endpoints policies, 4) Session policies. DOES evaluate: identity-based policies, permissions boundaries (if specified), inline/managed policies, Condition blocks. Exam tip: Bucket policy Deny is the most common cause of simulator showing Allow but real request getting Denied. |
| 5 | IAM Access Analyzer finding types: what does 'External Access' mean? | External Access = resource is accessible by principals outside your zone of trust (organization or specific account). Finding shows: 1) Which external principal has access, 2) What actions they can perform, 3) Through which policy (resource policy, ACL, etc.). Exam tip: Archive rules suppress expected external access findings without deleting them. |
| 6 | SCP Deny pattern: how to block Internet Gateway creation but allow all other EC2 actions? | {"Effect":"Deny","Action":"ec2:CreateInternetGateway","Resource":"*"}. Don't use Resource-level restrictions for creation actions (resource doesn't exist yet). Don't use NotAction with Deny (blocks everything except IGW creation). Exam tip: SCPs only use Deny - Allow statements in SCPs have no effect. |
| 7 | When does iam:PassRole permission matter for exam scenarios? | Required when creating resources that use IAM roles: EC2 instances (instance profile), Lambda functions (execution role), RDS databases (monitoring role), CodePipeline (service role). Error without it: InvalidPermission.NotFound or AccessDenied. Exam tip: PassRole must specify the exact role ARN being passed, not wildcard in production. |
| 8 | Permissions boundary vs. SCP: what's evaluated first and which wins? | Evaluation order: 1) Explicit Deny anywhere → Denied (SCP, boundary, identity policy), 2) SCP Allow → continue, 3) Permissions boundary Allow → continue, 4) Identity policy Allow → Allowed. Both work by intersection. Exam tip: SCP applies to entire account/OU, permissions boundary applies to specific IAM entity. SCP Deny cannot be overridden by boundary Allow. |
| 9 | S3 Block Public Access at organization level: can account admins override it? | No. When set at organization level, account-level and bucket-level Block Public Access settings cannot disable it. Organization-level is the strongest control. Applies to all buckets in all accounts. Exam tip: This is preferred over SCP for preventing public S3 access because it's purpose-built and cannot be bypassed through any policy mechanism. |
| 10 | NotAction in IAM policies: when is it useful for least-privilege? | Useful for: Allow everything EXCEPT specific dangerous actions. Example: {"Effect":"Allow","NotAction":["iam:*","organizations:*"],"Resource":"*"} allows all services except IAM and Organizations. Exam tip: Never use NotAction with Deny (creates confusing double negative). NotAction with Allow = deny listed actions, allow everything else. |
| 11 | IAM Access Analyzer: how to handle findings for trusted external accounts? | Create archive rule with criteria matching the trusted principal (account ID, organization ID, or federated user). Finding is automatically archived but remains accessible. Don't delete the policy (breaks business access). Don't disable analyzer. Exam tip: Cannot add external accounts to zone of trust after creation - use archive rules instead. |
| 12 | Resource Control Policies (RCPs): how are they different from SCPs? | RCPs: Control which principals can access resources in your organization (resource perspective). SCPs: Control what principals in your accounts can do (identity perspective). RCPs enforce who can access resources from outside the organization. Exam tip: RCPs were introduced in 2025 for resource-level access control across organization. SCPs remain the primary guardrail for identity-based restrictions. |
