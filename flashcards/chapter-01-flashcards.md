## Chapter 1: Detection: Multi-Account Threat Detection & OCSF Logging — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | GuardDuty finding severity ranges and corresponding severity labels? | Low: 0.1-3.9, Medium: 4.0-6.9, High: 7.0-8.9. Exam tests decision-making based on severity - High findings require immediate response, Medium need investigation, Low may be acceptable for public services. Remember: 7.0 is the cutoff for High. |
| 2 | CloudTrail Lake query engine SQL dialect and key differences from standard SQL? | Uses Presto/Trino SQL. Key differences: element_at(array, index) for array access (not bracket notation), resources array starts at index 1 (not 0), supports positional GROUP BY (1,2,3). Exam tests correct array access syntax for resources and requestParameters fields. |
| 3 | How do you access the assumed role ARN in a CloudTrail AssumeRole event in CloudTrail Lake? | element_at(resources, 1).ARN - NOT requestParameters.roleArn, NOT resources[0].arn. The assumed role is stored in the resources array as the first element. Exam tests correct field paths for common API calls. |
| 4 | GuardDuty multi-account: delegated administrator vs. individual account detectors? | Delegated admin (via Organizations): centralized management, automatic member enablement, findings visible in admin account. Individual detectors: decentralized, manual setup per account, no aggregation. Exam scenario: multi-account aggregation → use delegated admin. Single account → individual detector. |
| 5 | Security Hub vs. Security Lake for OCSF log correlation - when to use which? | Security Hub: aggregates findings from AWS services (GuardDuty, Inspector, etc.), ASFF format with OCSF mapping, real-time via EventBridge. Security Lake: data lake for OCSF logs, supports custom sources, query engine for complex correlation, S3-based storage. Exam: real-time alerting → Security Hub. Historical analysis/custom correlation → Security Lake. |
| 6 | Detective behavior graph data sources and retention period? | Sources: VPC Flow Logs, CloudTrail, GuardDuty findings. Retention: up to 1 year of data. Detective automatically ingests these sources when enabled. Exam tests which AWS services feed Detective (no need to manually configure log delivery) and use cases (relationship analysis, not real-time alerting). |
| 7 | VPC Flow Logs OCSF format vs. default format - key difference? | OCSF format: normalized schema (network class fields), compatible with Security Lake and OCSF-compliant tools. Default: AWS-specific fields. OCSF enables multi-cloud log correlation. Exam tests when OCSF is required (Security Lake integration, third-party SIEM with OCSF support). |
| 8 | GuardDuty Malware Protection: what does it scan and when? | Scans EBS volumes attached to EC2 instances for malware. Triggered by GuardDuty findings or on-demand. Creates snapshot, scans snapshot (no impact to running instance). Exam tests: Malware Protection is for detection (scanning), not prevention. Doesn't prevent port scanning, only detects malware on disk. |
| 9 | EventBridge rule pattern for Security Hub CRITICAL findings - exact syntax? | { "source": ["aws.securityhub"], "detail-type": ["Security Hub Findings - Imported"], "detail": { "findings": { "Severity": { "Label": ["CRITICAL"] } } } }. Exam tests correct nesting (findings object contains Severity object) and Label field (not Normalized or Original). |
| 10 | CloudTrail Lake event data store retention limits and pricing model? | Retention: 7 days to 7 years configurable. Pricing: pay per GB ingested + pay per GB scanned by queries. Cannot query data older than retention period. Exam tests cost optimization (long retention = higher storage cost, query optimization to scan less data). |
| 11 | GuardDuty threat intelligence feeds - how many and what types? | Uses multiple threat intel feeds: AWS-curated IP/domain reputation lists, CrowdStrike, Proofpoint. Automatically updated. Cannot disable or customize individual feeds. Exam tests: GuardDuty threat intel is automatic (no configuration needed), findings reference threat intel when malicious IPs detected. |
| 12 | Security Hub automated response: Custom Actions vs. EventBridge rules - use cases? | Custom Actions: manual analyst-triggered workflows (button in console → triggers EventBridge rule). EventBridge rules: automated real-time response (finding appears → rule triggers). Exam scenario: 'analyst reviews and decides' → Custom Action. 'Automatically remediate within X minutes' → EventBridge rule. |
