## Chapter 4: IAM Policy Evaluation Logic: The Decision Flow — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the IAM policy evaluation order from highest to lowest precedence? | 1. Explicit Deny (any policy type) 2. Service Control Policies (SCP) 3. Resource-based policies 4. Permissions boundaries 5. Session policies (for STS) 6. Identity-based policies. Exam tip: Explicit deny ALWAYS wins - it overrides all allows regardless of where it appears. |
| 2 | Cross-account S3 access requires which TWO policy configurations? | 1. Identity policy in SOURCE account allowing s3:* actions 2. Bucket policy in TARGET account allowing the source principal. Exam tip: Missing bucket policy is the most common reason for cross-account Access Denied errors. Both must exist. |
| 3 | What is the default behavior when no policy explicitly allows an AWS API request? | DENIED. AWS uses implicit (default) deny. Requests are denied unless an allow statement explicitly grants permission. Exam tip: This is why you need at least one allow policy - there are no default allows in AWS IAM. |
| 4 | Can session policies (used with STS AssumeRole) grant MORE permissions than the assumed role's identity policy? | NO. Session policies can only RESTRICT permissions, never expand them. Effective permissions = intersection of (role identity policy AND session policy). Exam tip: If exam asks 'can session policy allow X when role doesn't' - answer is NO. |
| 5 | What does a permissions boundary do in IAM? | Sets the MAXIMUM permissions a user/role can have. Acts as a ceiling. Even if identity policy grants ec2:*, a boundary with ec2:Describe* limits user to describes only. Exam tip: Boundaries don't grant permissions - they limit them. Effective = intersection of boundary AND identity policy. |
| 6 | CloudTrail shows errorCode: 'AccessDenied'. You've verified the identity policy allows the action. What should you check for next? | Look for an EXPLICIT DENY in: 1. SCPs (if in Organization) 2. Permissions boundary 3. Session policy (if using STS) 4. Another inline/managed policy. Exam tip: Explicit deny overrides all allows - if one exists anywhere, access is denied. |
| 7 | Cross-account IAM role assumption requires which policy in the TARGET account? | TRUST POLICY on the role allowing the source account's principal to assume it. Example: Principal: 'arn:aws:iam::SOURCE-ACCOUNT:role/RoleName'. Exam tip: Trust policy is a type of resource-based policy for IAM roles. Without it, AssumeRole fails even if source has sts:AssumeRole permission. |
| 8 | What AWS tool can you use to test IAM policy logic BEFORE deploying it to production users? | IAM Policy Simulator. Lets you input policies, specify actions/resources, and see allow/deny results. Tests all policy types including SCPs and boundaries. Exam tip: Simulator is for testing permissions. Access Analyzer is for finding external resource sharing. |
| 9 | An SCP denies 's3:DeleteBucket'. A user has identity policy allowing 's3:*'. Can the user delete buckets? | NO. SCPs are evaluated before identity policies. An explicit deny in an SCP cannot be overridden by any allow in an identity policy. SCP deny > identity allow. Exam tip: SCPs are organization/OU boundaries that member accounts cannot override. |
| 10 | For same-account S3 access, does the bucket need a bucket policy if the user has an identity policy allowing s3:GetObject? | NO. For same-account access, an identity policy allowing the action is sufficient. Bucket policies are required for: 1. Cross-account access 2. Anonymous/public access 3. Granting access without identity policies. Exam tip: Same account = identity policy enough. Cross account = need both. |
| 11 | What is the effective permission when a user has: Identity policy allows ec2:*, Permissions boundary allows ec2:RunInstances? | ONLY ec2:RunInstances. Effective permissions = INTERSECTION of identity policy AND permissions boundary. User can run instances but cannot terminate, stop, describe, etc. Exam tip: Boundary is a ceiling - you get the minimum of what both allow. |
| 12 | Which IAM policy types can contain EXPLICIT DENY statements? | ALL policy types: Identity-based, Resource-based, SCPs, Permissions boundaries, Session policies. Exam tip: Explicit deny in ANY of these overrides all allows. Look for deny statements when troubleshooting Access Denied errors. |
