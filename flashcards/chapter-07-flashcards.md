## Chapter 7: Data Protection: KMS, Encryption, and Key Management — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | KMS automatic key rotation frequency for symmetric customer managed keys? | Every 1 year (365 days). Backing key material rotates but CMK ID stays same. KMS automatically uses correct version for decrypt. Exam tip: Asymmetric keys and keys with imported material do NOT support automatic rotation. |
| 2 | Multi-region KMS key: primary vs replica key capabilities? | Primary: can create replicas, can be rotated. Replica: read-only copy, same key ID and material. Both: can encrypt/decrypt locally. Exam tip: Rotation on primary rotates ALL replicas. Used for cross-region DR and global applications. |
| 3 | KMS grant vs key policy for temporary access? | Grant: programmatic, temporary, no policy modification, can expire/retire, supports constraints. Key policy: permanent, requires policy update, account-wide. Exam tip: Use grants for temp delegation (Lambda function, 3rd party), key policy for permanent access. |
| 4 | Three KMS key material origin options? | 1) AWS_KMS (default, AWS generates) 2) EXTERNAL (you import from on-prem HSM) 3) AWS_CLOUDHSM (custom key store). Exam tip: Only AWS_KMS supports automatic rotation. EXTERNAL = BYOK = no auto rotation. |
| 5 | KMS key policy: what does Principal 'arn:aws:iam::123456789012:root' enable? | Enables IAM policies in account 123456789012 to grant access to the key. Delegates access control to IAM. Exam tip: Standard pattern. Without root account in policy, IAM policies alone cannot grant KMS access (dual authorization). |
| 6 | CloudHSM vs KMS FIPS 140-2 compliance levels? | CloudHSM: Level 3 (dedicated, single-tenant hardware). KMS: Level 2 (multi-tenant, managed). Exam tip: Level 3 requirement = must use CloudHSM. Custom key store uses CloudHSM but KMS operations = still Level 2. |
| 7 | KMS EncryptionContext condition key syntax in key policy? | "kms:EncryptionContext:key-name": "value". Example: "kms:EncryptionContext:Department": "Finance". Exam tip: For S3 SSE-KMS, use 's3:x-amz-server-side-encryption-context' to check object tags as encryption context. |
| 8 | Maximum number of grants per KMS key? | 50,000 grants per CMK. Exam tip: Grants are for temporary access. If hitting limit, you're likely misusing grants (should use key policy for permanent access). Retire old grants to stay under limit. |
| 9 | AWS managed key (aws/service) vs customer managed CMK: key policy control? | AWS managed: cannot modify key policy, AWS controls it, allows service + principals with service access. Customer managed: full control over key policy, define principals and conditions. Exam tip: Separation of duties requires customer managed CMK. |
| 10 | KMS encrypt/decrypt API request rate limit per second? | Varies by region: 5,500 to 100,000 req/sec (shared quota for symmetric encrypt/decrypt). Use S3 bucket keys or DynamoDB table keys to reduce requests. Exam tip: S3 bucket key reduces requests by ~99% for high-volume encryption scenarios. |
| 11 | Multi-region key: can you convert existing single-region key to multi-region? | NO. Must create new multi-region primary key. Cannot convert existing key. Exam tip: Plan for multi-region from start if needed. Migration requires re-encrypting data with new multi-region key. |
| 12 | KMS key policy evaluation logic when IAM policy allows but key policy is silent? | DENY (implicit deny). Both must allow (logical AND). Key policy must have account root as principal to enable IAM policy evaluation. Exam tip: This is dual authorization - resource policy (key policy) AND identity policy (IAM) must both allow. |
