## Chapter 5: IAM Advanced: Federation, ABAC, and Cross-Account Access — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | IAM Identity Center permission set vs IAM role - what's the relationship? | A permission set is a TEMPLATE. When you assign it to an account, Identity Center automatically creates an IAM role in that account with the permission set's policies. Role naming: AWSReservedSSO_PermissionSetName_randomhex. Exam tip: You manage permission sets centrally; Identity Center manages the actual roles. |
| 2 | What are the three required components for SAML federation to work with AWS? | 1) IAM SAML identity provider (IdP metadata uploaded to AWS), 2) IAM role with trust policy allowing sts:AssumeRoleWithSAML and trusting the SAML provider, 3) SAML assertion from IdP containing Role attribute: arn:aws:iam::account:role/rolename,arn:aws:iam::account:saml-provider/providername. Exam tip: Missing Role attribute = authentication succeeds but AssumeRole fails. |
| 3 | OIDC federation trust policy - what condition MUST you include for GitHub Actions? | StringEquals or StringLike on token.actions.githubusercontent.com:sub with value repo:orgname/reponame:ref:refs/heads/branchname. Also include aud condition: StringEquals token.actions.githubusercontent.com:aud: sts.amazonaws.com. Exam tip: Sub claim format is tested - repo:org/repo:ref:refs/heads/main for main branch only. |
| 4 | What service provides temporary AWS credentials to on-premises servers using X.509 certificates? | IAM Roles Anywhere. You create a trust anchor (your CA certificate or AWS Private CA), register it, then servers present X.509 certs to assume roles. Use credential helper tool on servers. Exam tip: Roles Anywhere = on-prem servers. OIDC = web apps/GitHub Actions. SAML = enterprise SSO. |
| 5 | External ID in cross-account trust policy - when is it required and what does it prevent? | Required for third-party access to customer accounts (SaaS vendors). Prevents confused deputy attack where vendor is tricked into accessing wrong customer's resources. Each customer gives vendor unique ExternalId, vendor must provide it when assuming role. Exam tip: Third-party + cross-account = External ID is best practice. |
| 6 | sts:AssumeRole vs sts:AssumeRoleWithSAML vs sts:AssumeRoleWithWebIdentity - when to use each? | AssumeRole: cross-account access from another AWS account. AssumeRoleWithSAML: enterprise SAML 2.0 federation (Okta, Azure AD). AssumeRoleWithWebIdentity: OIDC providers (Google, Facebook, Amazon Cognito). Exam tip: SAML = enterprise. WebIdentity = social/OIDC. Regular AssumeRole = AWS account to AWS account. |
| 7 | ABAC policy condition: how do you reference a principal's session tag vs a resource's tag? | Principal tag: aws:PrincipalTag/tagkey (e.g., aws:PrincipalTag/Department). Resource tag: service:ResourceTag/tagkey (e.g., s3:ResourceTag/Project). Session tags passed via AssumeRole become PrincipalTag. Exam tip: PrincipalTag = who is making request. ResourceTag = what is being accessed. |
| 8 | What S3 condition enforces that objects MUST be created with specific tags? | s3:x-amz-tagging with ForAllValues:StringEquals or ForAnyValue:StringEquals. Example: "Condition": {"StringEquals": {"s3:x-amz-tagging/Environment": "Production"}}. Exam tip: Must combine with permissions boundary to prevent bypassing. x-amz-tagging = tags on PutObject. ResourceTag = tags on existing object. |
| 9 | Session policy in STS AssumeRole - what does it do? | Reduces (never expands) permissions during that session only. Passed as Policy parameter in AssumeRole API call. Effective permissions = intersection of role's permission policy AND session policy. Max size 2048 characters. Exam tip: Session policies restrict, cannot grant new permissions beyond role's policy. |
| 10 | Maximum session duration for an assumed role? | 12 hours for IAM roles assumed by AWS accounts/services. 1 hour default for federation (can extend to 12 hours if role's MaxSessionDuration allows). CLI: --duration-seconds parameter (900-43200 seconds). Exam tip: Federation defaults to 1 hour. Regular AssumeRole can request up to role's max (default 1 hour, max 12 hours). |
| 11 | IAM Identity Center session duration limits? | Session duration set in permission set: 1-12 hours. Application session duration (portal): 1-7 days. Relay state duration: 240 seconds for SAML assertion redirect. Exam tip: Permission set session = 12 hours max. Portal session = 7 days max. Different from role session duration. |
| 12 | Trust policy for IAM Roles Anywhere - what principal type? | Principal type: Service, value: rolesanywhere.amazonaws.com. Action: sts:AssumeRole, sts:TagSession, sts:SetSourceIdentity. Condition: StringEquals on rolesanywhere:CertificateField/Subject with expected DN. Exam tip: Not Federated principal type - uses Service principal for Roles Anywhere service. |
